# XENOFIELD V4.1b — Blend / Mask / SkySynth Interaction Rework

## Scope

This release extends the V4.1a SkySynth UI without changing the project's core purpose: a live HDR environment feeding alien-liquid and energy-field rendering.

## SkySynth interaction changes

- SkySynth synthesis parameters are horizontal sliders again.
- The SkySynth window can be resized vertically by dragging its dedicated bottom-edge handle.
- Horizontal resize is intentionally not exposed by that handle, preserving the compact side-window footprint.
- Direct numeric entry, editable slider windows, editable hard safety caps, Functional Extremums and tooltips remain intact.

## Practical blend-mode bank

The compositing system is now shared by several renderer elements instead of being local to SkyNoixture.

### Implemented modes (34)

Normal, Dissolve,
Lighten Only, Luma/Luminance Lighten Only, Screen, Dodge, Addition,
Darken Only, Luma/Luminance Darken Only, Multiply, Burn, Linear Burn,
Overlay, Soft Light, Hard Light, Vivid Light, Pin Light, Linear Light, Hard Mix,
Difference, Exclusion, Subtract, Grain Extract, Grain Merge, Divide,
HSV Hue, HSV Saturation, HSL Color, HSV Value,
LCh Hue, LCh Chroma, LCh Color, LCh Lightness, and Luminance.

The arithmetic/contrast mode behavior was implemented with the public GIMP layer-mode implementation as a semantic reference:
`GNOME/gimp/app/operations/layer-modes/gimpoperationlayermode-blend.c`.

The LCh-style component modes use Oklab as the underlying perceptual opponent space. This gives useful hue/chroma/lightness replacement behavior with a compact WebGPU implementation and no separate ICC/color-management runtime.

### Pictured modes not implemented

Color Erase, Erase, Merge and Split are not ordinary RGB blend functions. In GIMP they belong to alpha/compositing semantics. XENOFIELD's current layers are opaque HDR radiance fields, so implementing same-name RGB approximations would be misleading. They are deferred until an explicit alpha-bearing layer graph exists.

## Blend targets

The mode bank can be assigned independently to:

- SkyMixer (SkySynth / HDRI composition)
- SkyNoixture
- procedural cloud layer
- liquid surface foam

This is intentionally represented as a common bank so future effects can join the same compositing contract rather than growing one-off shader modes.

## Live mask channel

SkyMixer now exposes one live mask generator. The same generated mask can be routed to any combination of Mixer, SkyNoixture, Clouds and Foam.

### Mask sources

- Constant
- SkySynth luminance
- HDRI luminance
- mixed-environment luminance
- SkyNoixture
- procedural cloud field
- Perlin
- Billow
- Ridge
- Weave
- vertical gradient
- radial gradient

### Source composition

Two source channels are evaluated continuously. Source A and Source B can be combined by:

- Mix
- Multiply
- Screen
- Addition
- Difference
- Minimum
- Maximum

A separate Source Mix value controls the contribution ratio where applicable.

### Image manipulation

After source mixing, the mask path provides:

- Brightness
- Contrast
- Gamma
- Threshold
- Softness
- Scale
- Drift
- Invert

These controls operate on the live shader-side mask and are not destructive edits of the environment sources.

## Performance design

- Blend modes are implemented as small scalar/vector math branches inside the existing fragment path; no new full-screen render targets are allocated per blend mode.
- Mask sources reuse already resident environment/detail textures and procedural fields.
- A single mask is evaluated and routed by a bit field rather than creating separate masks for every target.
- Dissolve uses a deterministic hash rather than an additional noise texture.
- Oklab component modes are more expensive than simple arithmetic modes but remain a small per-pixel ALU cost with no extra GPU passes.
