## Proof boundary

The current container has no usable Vulkan driver. The supplied Dawn binding can create its **null backend**, which validates shader/pipeline/resource/command compatibility but does **not** provide meaningful rendered pixels or hardware timing. Chromium in this container also exposes no `navigator.gpu`, even with unsafe-WebGPU/software flags.

Therefore this V4.4b validation **does not claim**:

- target-GPU performance;
- browser WebGPU presentation;
- pixel equivalence to the reference demo;
- hardware-rendered evidence for the new cloud volume.

The inherited V4.4a package retains its earlier software-WebGPU rendering evidence for the base Kinetic Compositor. The V4.4b additions were separately regression-tested and Dawn command-validated here.

## Reference fidelity boundary

The dedicated cloud renderer preserves the reference control semantics, density-stage ordering, cache generation/interpolation model, stochastic primary ray entry and source-style live light march. Its compact 4D procedural helpers are a Xenofield re-expression rather than a byte-identical copy of Blender's internal noise implementation. The video preset is intended to reproduce the same *family* of hollow cellular/membrane structures, not identical voxel values.
