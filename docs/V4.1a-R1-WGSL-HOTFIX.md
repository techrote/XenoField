# XENOFIELD V4.1a-r1 — WGSL startup hotfix

## Symptom

On a WebGPU-capable machine the app showed the full-screen CPU SkySynth preview instead of the mapped environment and liquid surface. The runtime notification reported:

`environment / sky: ... 'meta' is a reserved keyword`

## Root cause

The V4.1a SkyNoixture shader introduced two local WGSL variables named `meta`. `meta` is a reserved WGSL keyword. Because the shared `SCENE` shader source is used by both the sky and liquid pipelines, this caused renderer initialization to fail before the first WebGPU frame. The application then correctly entered its CPU environment-preview fallback, but its old status text misleadingly labelled all renderer initialization failures as "WebGPU unavailable".

## Fix

- Renamed the two WGSL locals:
  - `meta` -> `modeCode`
  - `meta` -> `blendCode`
- Replaced the narrow reserved-word test with a comprehensive WGSL reserved-identifier scan over generated SKY, LIQUID, POST and FFT shader sources.
- Changed CPU fallback diagnostics so a machine with `navigator.gpu` now reports **GPU RENDERER INITIALISATION FAILED** rather than **WEBGPU UNAVAILABLE** when shader/pipeline construction fails.
- Regenerated the single-file standalone build from the corrected source.

## Validation

- Node tests: 103 / 103 pass.
- Static/source contracts: 402 pass.
- Browser UI/component checks: 51 / 51 pass.
- The packaged source and standalone contain no `let meta` / `var meta` WGSL declarations.

The test host still does not expose a usable WebGPU adapter to Chromium, so a genuine rendered WebGPU frame cannot be certified here. The specific compilation error shown in the supplied screenshot is removed and now guarded by the static checker.
