# XENOFIELD V4.2a — Modular Presets, UI Cleanup, HDRI / EXR Reliability

## Scope

V4.2a responds to two practical problems in V4.1b:

1. the authoring UI had become difficult to navigate as compositing, masking and surface controls accumulated;
2. HDRI/EXR import could appear non-functional because imported environment work shared lifecycle/revision state with the continuously running SkySynth path, and EXR publication was not treated consistently as an imported environment in the main runtime.

The liquid renderer and V4.1b blend/mask functionality are retained. The refactor is primarily about **ownership, authoring, persistence and environment input reliability**.

## UI cleanup

The authoring model is now eleven independently presettable functional panels:

- SkySynth
- Modulator
- SkyMixer
- SkyNoixture
- Mask
- Motion
- Material
- Surface
- Atmosphere
- Output
- LUT

The Liquid window is reduced to five tabs: Motion, Material, Surface, Atmos, Output. SkyMixer, SkyNoixture, Mask and Modulator remain attached SkySynth sidepanels instead of occupying the main liquid control surface.

Every functional panel now has one compact preset row with:

- preset selector
- LOAD
- SAVE
- delete-user-preset

The top bar has a separate global-stack selector with LOAD / SAVE / delete-user-stack.

Preset menus are refreshed only when their banks change; slider movement no longer rebuilds every preset dropdown on each input event.

## Panel presets

Panel presets own only the settings displayed by that subsystem. A Material preset cannot silently rewrite SkySynth, Atmosphere or Motion parameters, for example.

The presets deliberately cover materially different uses of each subsystem: calm and violent motion, orbital and field modes, mirror/opal/petroleum materials, conventional and emissive foam, multiple mask routing strategies, real/synthetic environment composition, dark and luminous cloud treatments, low-cost and high-detail output budgets, and all ten LUT families.

## Global preset stacks

Global presets are no longer flat settings snapshots. Each global stores exactly one **panel preset name per panel**.

5. SULFUR BLOOM

8. OPAL WORLD
9. INFRARED PLANET
10. VOID RESONATOR
11. HDRI SYNTH FUSION

A user may replace one panel preset after loading a global without losing the conceptual structure of the rest of the stack.

When saving a global stack while one or more panels are `Custom`, XENOFIELD first captures those custom panels as named user panel presets, then writes the global stack as a list of names. This preserves the requested list-of-panel-presets model even for user-authored worlds.

## HDRI / EXR fixes

### Direct import publication

HDRI file imports now bypass the continuously scheduled SkySynth worker queue. Decoding and publishing an imported panorama cannot be starved by the synth frame producer.

A bad import does not replace the current valid environment.

### Main runtime classification

Any environment frame whose type is not the SkySynth `frame` type is classified as an imported HDRI source. This fixes EXR frames being generated successfully but not receiving the imported-environment handling path.

### Local decode paths

- Radiance HDR / RGBE: bundled local decoder.
- OpenEXR NONE / RLE / ZIPS / ZIP scanline files: bundled local decoder.
- PIZ / PXR24 EXR: extended hdrify fallback when network access is available.
- PNG / JPEG / WebP: browser image decode to linear RGB.

The local EXR implementation follows the OpenEXR scanline layout and uses predictor/reorder semantics consistent with the hdrify reference implementation for RLE/ZIP data. An included uncompressed 64×32 calibration EXR exercises the full browser file-input → decode → environment-publication path without network access.

## Persistence

State format is version 4. It stores:

- settings
- slider windows
- active hard safety caps
- functional extremums
- UI preferences
- ten LUTs
- user panel preset banks
- current panel preset selections
- user global stacks
- active global stack name

V4.1b browser settings are migrated into V4.2a settings, but their new panel/global selections begin as Custom because the older storage format had no modular preset identity.
