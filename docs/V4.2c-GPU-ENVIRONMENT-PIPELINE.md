# XENOFIELD V4.2c — GPU Environment Pipeline

## Purpose
V4.2c targets the two profiler-identified frame-time regressions in V4.2b:

1. CPU SkySynth upsampling / filtering / mip generation.
2. CPU `PreviewDraw` compositing of the SkySynth preview.

The performance target remains 60 FPS with materially improved 1% lows; this build changes the architecture toward that target but cannot certify hardware-specific FPS in the development container.

## Runtime pipeline

### Before
Low-resolution SkySynth generation was followed by CPU reconstruction, CPU NL processing, CPU mip generation, half-float packing, upload, and a separate CPU pixel-by-pixel preview compositor.

### V4.2c
The worker now emits the low-resolution HDR SkySynth source only. The WebGPU renderer performs:

- Stage A upsampling
- optional nonlinear filter
- Stage B upsampling
- final NL stage when selected
- environment mip generation
- sky / mixer / Noixture / mask / cloud compositing
- SkySynth preview rendering

The preview is a WebGPU render pass sampling the same environment system as the main renderer. No CPU `ImageData` preview is executed while WebGPU is active.

## GPU reconstruction modes

- Nearest
- Linear / hardware bilinear
- Smoothstep bilinear
- Bicubic
- Catmull-Rom
- Lanczos2
- Optimised edge-aware nonlinear filter

The two upsampling stages remain independently selectable and the NL filter can be inserted PRE / MID / POST.

## Preview toggle
Clicking the SkySynth preview disables it. The preview area collapses to one text line plus margin and displays `CLICK TO ENABLE PREVIEW`. The MOD meter collapses with the preview. Disabling the preview also suppresses its GPU render pass.

## Modulation display
The modulation display now updates at 10 Hz and uses an exponential smoothing step between incoming worker modulation values. CSS interpolation smooths the meter motion between UI updates.

## HDRI / EXR size
The file-size admission limit is now 2 GiB. Browser memory/address-space availability still determines whether very large EXRs can actually be decoded; the larger limit does not bypass browser allocation limits.

## Profiling
The live profiler now includes `gpuEnvironmentEncodeMs` in addition to worker time, upload time, render CPU time and fallback-only PreviewDraw time. This metric is CPU command-encoding time for the GPU environment passes, not a timestamp-query GPU execution duration.

## Validation
- 125 / 125 Node tests passed.
- 925 static/source/WGSL contracts passed.
- Standalone HTML regenerated from the same source.
- Headless Chromium startup smoke test: no page errors, boot overlay clears, 83 schema controls generated, preview disable interaction works.

## Remaining CPU work
SkySynth mathematical source generation, low-resolution spatial/temporal smoothing, half-float packing and EXR/HDR decoding remain on CPU. These are intentionally retained for this pass because they operate on the small source image or are one-time decode operations; the former hot-path reconstruction and preview work is now GPU-side.
