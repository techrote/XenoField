# XENOFIELD V4.2c-r2 — WGSL + GPU SkySynth hotfix

## Root causes fixed

### 1. GPU environment reconstruction shader did not compile
The Lanczos2 WGSL function declared two local variables in one `let` statement:

```wgsl
let dx=...,dy=...;
```

WGSL requires one variable declaration per statement. Both Firefox and Chrome rejected the module before the renderer could initialise, forcing the application into CPU-environment fallback mode.

The declaration is now split into independent statements. The static shader checker now rejects this declaration pattern across all packaged WGSL modules.

### 2. The ~66 ms "worker" timing was fallback CPU SkySynth work
Because the GPU renderer never initialised, SkySynth continued through the CPU worker. At high source resolutions this still performs source generation, CPU spatial smoothing and half-float packing. That is why Worker time remained large even after GPU upsampling had nominally been added.

V4.2c-r2 moves the SkySynth source generation itself onto WebGPU when the renderer is available. The CPU worker is now idle during the normal WebGPU path and remains only as a compatibility/fallback path when WebGPU is unavailable or the renderer cannot initialise.

## GPU SkySynth path

The live WebGPU path is now:

1. GPU SkySynth source generation at Source Width.
2. GPU temporal blend using ping-pong source textures.
3. GPU spatial smoothing.
4. GPU Upsample A.
5. Optional GPU NL filter at PRE/MID/POST.
6. GPU Upsample B.
7. GPU mip generation.
8. Shared GPU environment consumed by sky, liquid reflection and preview.

The active LUT is uploaded only when its palette changes.

## Preview behaviour

- GPU preview rendering is capped to roughly 15 Hz.
- It is skipped when the preview canvas is not visible.
- Clicking the preview still disables it and collapses its UI.
- The performance-profiler chart is rate-limited to 10 Hz and is not painted while hidden.
- CPU fallback preview is reduced to 128×64 at 5 Hz and is also skipped when hidden.

This specifically addresses the observation that the expanded preview/UI could disturb frame pacing while minimising it improved the main output.

## Reconstruction safety

The reconstruction parameter ring was increased from 8 to 24 unique uniform buffers so multi-pass upsampling + filtering + mip generation cannot wrap and accidentally reuse a buffer within the same submitted command stream.

## EXR / HDRI

The 2 GiB file-admission limit from V4.2c is retained. Common EXR scanline formats remain locally decoded; extended compression fallback behaviour is unchanged.

## Validation

- 125 / 125 Node tests passed.
- 969 static/source/WGSL contracts passed.
- 17 / 17 bounded Chromium DOM/component + local EXR checks passed.
- Standalone regenerated from the patched source.

This validation host has no usable WebGPU adapter, so actual WebGPU shader compilation and frame-time measurements still need to be confirmed on a WebGPU-capable machine. The exact WGSL syntax error reported by Firefox/Chrome is now regression-checked in source.
