# V4.4a reference and validation provenance

## Procedural-clouds architectural reference

The implementation prompt names `jeantimex/procedural-clouds`. Its `main.js`, `shaders/cloud.wgsl` and `LICENSE` were inspected. The useful concepts are GPU density caching, ping-pong generations, decoupled update cadence, interpolation, stochastic entry and early transmittance exit. Its nested sample-by-sample light march was not adopted as the normal Xenofield path.

Reference: https://github.com/jeantimex/procedural-clouds

Inspected `main.js` content blob: `863e9fe8e4c4ab1ff2a1edb5cdf7a50b8cbeca43`.
Inspected license blob: `d5c6509942f88b600b167b3c11445bffd8a3efed`.

The new volume/control/compositor modules are independently implemented around Xenofield's resource model; the reference renderer is not bundled as a second renderer. Its MIT notice is retained below as provenance. It is **not** a declaration that the entire existing Xenofield/ABYSSAL codebase has been relicensed under MIT. Earlier provenance remains in `REFERENCE-NOTES.md` and `ABYSSAL-UPSTREAM.md`.

## Optional native validation tool

Offscreen tests used the official Dawn Node binding from `dawn-gpu/node-webgpu`, release/tag v0.6.0, workflow run `33194785045`, Linux x64 artifact `9696068521`. The downloaded archive SHA-256 was verified:

`0aa733db21d322f9aa8af40824ec4cb7055e3c94a3bfd3d1eee231c904f87152`

The actual adapter was Google SwiftShader over Vulkan. The addon and its archive are not included in this release and are not application dependencies. The supplied harness accepts an externally installed native binding. Software-native timings must not be quoted as target hardware performance.
