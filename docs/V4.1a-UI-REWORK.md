# XENOFIELD V4.1a — UI / SkySynth Refactor

## Delivered scope

### Presentation

- Renamed Keybed to **SkySynth** throughout the active interface.
- Changed the primary small-label typography to an uppercase, condensed/block-oriented system stack.
- Moved SkySynth resolution and generator FPS into the SkySynth titlebar.
- Made the primary SkySynth synthesis sliders vertical.
- Reworked key controls into compact function pairs:
  - function name above each pair,
  - `+ / −` action in the left corner,
  - keyboard key in the right corner,
  - reduced button height.
- Narrowed the upsampling selector and moved spatial/temporal smoothing controls next to it.

### Tooltips / UI settings

- Numeric sliders, parameter buttons, selects and generated controls receive tooltip metadata.
- Parameter tooltips use the same descriptive source as the advanced information window.
- Added **UI SETTINGS → TOOLTIPS**. Disabling tooltips removes active `title` attributes without discarding the underlying descriptions.
- Tooltip preference persists in browser/project state.

### Advanced parameter control

The old range dialog now acts as an experimental parameter-inspection panel.

For each numeric parameter it exposes:

1. Effect description / usage notes.
2. Slider-window min/max.
3. Editable active hard safety min/max.
4. Immutable engineering bounds for reference.
5. Functional Extremums min/max, stored as reference metadata only.

Safety caps cannot exceed the immutable engineering bounds and cannot be changed so that they exclude the parameter's current value. Functional Extremums do not participate in validation or clamping.

### Modulator

- Moved Modulation into a SkySynth-attached popout sidepanel.
- Added signed live modulation bar to the panel.
- Added a vertical modulation meter beside the SkySynth preview.
- Clicking the SkySynth meter toggles modulation on/off.

### SkyNoixture

Added a SkySynth-attached compositing panel with:

- enable toggle,
- Perlin / Billow / Ridge / Weave sources,
- Multiply / Screen / Add / Soft-light blending,
- amount, scale, contrast, drift and tint controls.

The GPU path applies SkyNoixture after environment mixing, so the same result feeds the visible sky and liquid reflection lookup.

### SkyMixer

Added a SkySynth-attached environment mixer. V4.1a intentionally starts with one operation:

`SkySynth  ← transparency →  HDRI`

The GPU keeps independent plasma and HDRI textures and selects/blends them in the shared environment shader. The mixer panel reserves an extension area for future masks, channel operations, feedback, warps and multi-source graphs.

### EXR

The file picker accepts `.exr`. EXR decoding is implemented through an on-demand dynamic import of **hdrify 0.12.1**. This keeps the normal Xenofield source tree dependency-free but means EXR decoding currently requires network access to `esm.sh` on first use. `.hdr/.rgbe`, PNG, JPEG and WebP decoding remain local.

A failed EXR import is fail-safe: it does not replace the last valid environment.

## Renderer integration

The shared scene uniform block increased to 104 floats (416 bytes), adding mixer and SkyNoixture controls while retaining 16-byte vec4 alignment.

The scene bind group now carries two environment textures:

- plasma/SkySynth map,
- HDRI/EXR map.

Environment backpressure is tracked independently per source so a slow GPU cannot create an unbounded frame queue. Only the newest pending update for each mixer source is retained.

The post-process shader no longer inherits scene-only detail-texture bindings; scene and post WGSL declarations are split to match their separate bind-group layouts.
