# V4.4a architecture and control reference

Status: implemented in the supplied V4.3b workspace. This document describes the delivered code, including deliberate approximations. It does not claim physical correctness, measured speedups or a closed-mesh volumetric simulation.

## Frame and ownership

```text
FFT when a surface or a spectral-volume source needs it
    → single-sample SceneAux geometry
    → optional min-depth pyramid / scene-material mask preparation
    → sky + surface HDR, with optional native MSAA4 resolve
    → due density generation / due cached lighting
    → sparse low-resolution volume raymarch
    → conservative volume reconstruction
    → depth shaping / volume composition / RGB distortion
    → conservative scene reconstruction
    → separate artistic feedback
    → positive bloom / dark bloom / LUT shaping / optional debug
    → spatial AA downsample
    → existing HDR display
    → due SkySynth/environment updates for the next frame
```

The depth pyramid is prepared before the HDR material pass when current-depth masks need it. It depends only on SceneAux, so this does not add an HDR dependency. The existing environment pipeline remains after display encoding: scene and cache generation consume the last completed environment, not a texture being simultaneously reconstructed.

Stable scene accumulation precedes destructive feedback and signed colour changes. Artistic feedback never writes into the conservative scene or volume history. A frame contains one new temporal subpixel sample; selecting Temporal32 does not run thirty-two complete renders per frame.

Field mode retains its no-geometry path. It also skips FFT unless an enabled volume generator explicitly consumes a spectral source. Pausing stops spectral/volume time and recursive feedback advancement; conservative accumulation may still converge.

`renderer.js` remains the device/scene owner. It owns the original scene resources, HDR target, multisample variants, presentation resolve and timestamp query system. Optional owners use its retirement queue so resources are not destroyed while submitted work still uses them. Production rendering never imports the texture-readback helpers in `tools/`.

## SceneAux is not a deferred renderer

The prepass shares the actual liquid/mesh vertex paths, including displacement. It omits material shading. Its outputs are **R32Float camera-ray distance**, **RGBA16Float world normal XYZ + surface energy**, and a private single-sample depth24plus attachment. “Linear depth” here means metric distance along the camera ray, not view-space Z and not nonlinear hardware depth.

The sky has a finite far sentinel. The HDR scene may use multisampled colour and depth; its auxiliary signals remain single-sampled. A small min-depth pyramid supports silhouettes and multi-scale effects. Odd image sizes include the source edge texels rather than dropping their last row/column. There is no ABYSSAL world-object visibility/culling system.

Depth controls support near/far remapping, inversion, gamma, threshold/softness, bands, drift, quantization, edge radius and strength. Operators include colour/LUT by depth, posterization, bands, contours, glow/darkening, desaturation, hue, fog and inversion. Their mask inputs are the same source vocabulary used elsewhere.

## Cached 3D field

The format probe first compiles and allocates an RGBA8Unorm storage/filtering path, then falls back to RGBA16Float on failure. All four channels are used: **R density; G cached illumination; B structure; A emission**. Two generations plus a lighting scratch cache are allocated persistently. Density mips are generated only when the chosen cached light method needs them.

The generator offers Perlin, billow, ridge, Voronoi, cellular separation, spectral GPU state, projection, Noixtur atlas fields, SkySynth radiance and deterministic hash. A second source can be mixed, multiplied, added, differenced or threshold-XORed. Shaping includes threshold/softness, power, inversion, quantization, folding, absolute/difference shaping, mirrored/repeated coordinates and coordinate warp.

Density and lighting have independent clocks. Slow rates can reach 0.1 Hz through numeric entry/range editing. Rate changes, generator edits and lighting edits invalidate the corresponding cache immediately. There is no catch-up burst after a stall. Generation interpolation adds a deliberate generation of latency in return for smooth motion; disabling it exposes stepped cache updates.

Lighting choices are density-gradient shading, a short cached march, a density-mip attenuation approximation, unlit, and an explicitly expensive live march. Only the last performs nested light sampling during the pixel raymarch. Environment colour uses the selected SkySynth/HDRI contribution; it is a cheap field tint, not a physically integrated scattering solution.

Sparse marching uses one of seven step counts and six resolution divisors. It includes entry jitter, per-cell dropout, empty samples, transmittance termination, scene-depth clipping and weighted volume depth. It writes radiance/opacity, integrated field signals and ray depth. Reconstruction uses separate history and depth-aware upsampling. Fine detail is injected from the existing atlas, hashes, blue noise, Noixtur proxies, depth/normal edges or pattern channels instead of increasing the 3D cache.

### Placement semantics

| Mode | Actual construction |
|---|---|
| World Box | Axis-aligned finite world-space box with configurable centre and size. |
| Camera Slab | Camera-facing slab; XY maps across the screen and Z through its bounded ray span. |
| Surface Shell | A visible-surface depth interval in front of SceneAux geometry. Not restricted to a horizontal plane. |
| Planet Shell | Analytic shell around the existing radius-120 planet, with offset and thickness. |
| Mesh Local | Axis-aligned box around the conditioned mesh, using mesh scale and shell thickness. |
| Mesh Normal Shell | Visible-depth shell with thickness adjusted by the sampled normal/ray facing. |
| Screen Extrusion | Screen XY extruded through a configurable depth interval. |
| Infinite Tiled | Repeated world-coordinate field inside a finite ray budget/range. |

Surface and mesh-normal shells are **screen-visible approximations**, not signed-distance fields. They cannot reconstruct hidden backsides or arbitrary closed-mesh interiors. The volume projection helper shares all twenty existing mappings, but a cache voxel has no imported UV chart or actual mesh normal: it supplies planar UV and radial-normal proxies where the helper requires them. Changing mapping controls still affects the shared cache path.

## History, masks and signed composition

Stable reconstruction uses previous/current camera transforms, metric depth rejection, sky/disocclusion classification, a 3×3 neighbourhood clamp, luminance confidence and responsiveness. Camera cuts, resize/quality transitions, mode/sampling changes and rebuilt mesh geometry invalidate history. There are no explicit deforming-surface motion vectors; rapidly animated FFT/projection/noise content relies on conservative rejection and responsiveness.

Feedback adds independent persistence, layer opacity, decay, gain, hue rotation, zoom, rotation, XY drift, warp, threshold, mask and optional depth rejection. Mix, Add, Screen, Multiply, Difference, Max and Min are distinct modes. Colour is bounded to avoid half-float overflow under extreme gain. The history is a creative instrument rather than an optical simulation.

The shared mask router adds depth, inverse depth, bands/sine/quantized depth, gradients/edges/silhouette, normal facing/edges, surface energy, four volume channels and history/difference/feedback signals. Existing source A/B mixing and mask adjustments remain available. Mixer, Noixtur, foam and cloud material routes can consume the prepared screen-space result.

**Dependency boundary:** scene material masks see current SceneAux and previous completed volume/history. Density-cache mask injection also uses a prepared mask to avoid reading its own new output. Later compositor passes can consume current volume/history. Screen-space masks are not secretly rebaked into a globally reusable environment panorama. Old procedural cloud/Noixtur mask names use inexpensive field/atlas proxies in the generic compositor rather than reproducing every surface shader octave there.

Volume interpretations include alpha veil, add, screen, multiply, difference, absorption, displacement, LUT modulation and masking. Positive bloom and dark bloom each own a reduced-resolution mask, normalized separable blur and composition step. Dark bloom multiplies local scene radiance by blurred absorption; it is not a vignette. Distortion has independent source, scale, threshold, direction/drift, depth response, RGB offsets and foreground protection.

## AA, filtering and allocation

Native scene sample counts are 1 and 4. SSAA targets pixel area 1, 2, 4 or 8; each axis scales by the square root. Temporal targets are Off, 2, 4, 8, 16 and 32. The three budgets can be combined. Downsampling offers area Box, Bilinear, Catmull–Rom and Lanczos2. Sharpening remains in the existing display stage.

Nearest, Bilinear, Trilinear and AF2/4/8/16 are centralized sampler descriptors. Native anisotropic modes use linear min/mag/mipmap filtering. Manual AF32 is an explicit derivative-footprint sampling loop confined to selected 2D surface-detail paths. Explicit-LOD environment and 3D cache sampling do not incur those thirty-two taps.

The pure sizing planner accounts for HDR/MSAA, auxiliary data, scratch images, independent histories, bloom, volume targets, a worst-case fallback cache format and a fixed allowance for base resources. It bounds both internal and output dimensions by `device.limits.maxTextureDimension2D`, pixel budget and configured bytes. Normally 32% of the texture budget is reserved for retirement/transition headroom. It is an estimate: transient driver memory, implementation overhead and unusually large existing mesh/environment inputs are not queried as VRAM usage.

Allocation signatures use actual resulting dimensions, not arbitrary parameter changes. Rapid size changes are debounced. Disabled passes do not dispatch their normal work; their optional screen/cache/history resources are released when no longer needed. Shader initialization is error-scoped and fail-open. A genuine device loss still requires renderer restart; no software guard can guarantee that a driver allocation or device failure never occurs.

## Diagnostics and practical boundaries

The eighteen view choices include Final, depth/pyramid, auxiliary data, normals/energy, volume density/light/structure/emission, raw volume, stable history/rejection, feedback, bloom masks, distortion vectors and router output. Volume channel views show ray-integrated cached signals, not a 3D slice editor. A disabled producer shows a neutral surface instead of silently enabling a costly pass.

Each significant pass has a timing identity. The UI marks inactive stages idle and does not invent timings when timestamp queries are unavailable. Its active profiled sum is not presented as whole-frame wall time. Render dimensions, effective SSAA, cache format/dimensions, ray target, update cadence, history size/age and estimated bytes are reported separately.

The software-native test suite establishes shader compilation, API/binding/resource legality, finite output and the tested pixel contracts. Full browser presentation, driver diversity, long-duration high-resolution feedback, real VRAM pressure, unexpected device loss and subjective tuning on the target GPU remain deployment checks. No measured “visual complexity per millisecond” or hardware speedup is asserted.
